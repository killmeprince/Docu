# Backend MVP smoke notes

Этот smoke test прогоняет полный рабочий цикл текущего backend MVP:

1. JWT login для employee / approver / admin.
2. Создание документа как карточки с версией и вложением.
3. Чтение карточки и списка версий.
4. Обновление черновика с созданием новой версии.
5. Поиск по регистрационному номеру.
6. Отправка на согласование.
7. Проверка запрета редактирования в статусе IN_APPROVAL.
8. Обработка шага согласования через REWORK.
9. Доработка документа автором и повторная отправка.
10. Итоговое APPROVE.
11. Проверка аудита.
12. Проверка отчетности и admin endpoints.
13. Проверка негативных сценариев доступа.

## Что smoke test не покрывает

- `REJECT` ветку как отдельный завершающий сценарий.
- Загрузку и скачивание файла отдельным GET `/api/files/{filename}`.
- Создание admin-ом новых пользователей и типов документов.
- Поведение inactive users.
- Сложные многошаговые маршруты.
- Архивирование как отдельный бизнес-процесс.

## Первые продуктовые замечания по backend

1. Нет отдельного reference endpoint для document types обычным пользователям. Сейчас employee не может штатно получить список типов, а фронт вынужден хардкодить `documentTypeId = 1`.
2. Отчетность доступна только approver/admin, но фронт дергает `/reports/summary` для всех и проглатывает ошибку. Это уже не backend-bug, а несовпадение контракта между frontend и backend.
3. Нет специализированного endpoint для "мои pending approval tasks". Сейчас approver получает документы косвенно через общий поиск.
4. Архивный статус есть в модели, но полноценного сценария перевода документа в `ARCHIVED` пока нет.
